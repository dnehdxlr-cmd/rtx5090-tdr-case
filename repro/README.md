# CUDA 부하 파일

`cuda_probe.py`는 2026-11-10 비교 시험에서 사용한 원본이다. 다음 SHA-256과 일치하며, 공유 자료 작성 과정에서 시험을 다시 실행하지 않았다.

`C119A98DF9339448568409564B2F4732A03D3574F7ED24B745EA29012B57B3A3`

당시 환경은 PyTorch 2.13.0+cu130 / CUDA 13.0 / cuDNN 9.20 / RTX 5090이었다. 이 패키지에는 환경 설치 명령이나 의존성 잠금 파일이 없다. 버전·설정이 바뀐 환경은 동일 조건으로 간주할 수 없다.

아래는 당시 CUDA 세 단계의 명령 형식이다. `python`은 검증된 기존 Python 환경을 가리켜야 한다. NVENC·D3D11 시험과 이벤트 감시·외부 시간 제한을 수행한 원래 감독 스크립트 전체는 포함하지 않았으므로, 이 명령만으로 전체 5단계 수집 절차가 재현되지는 않는다.

```powershell
python -I -u .\repro\cuda_probe.py transfer --seconds 15
python -I -u .\repro\cuda_probe.py matmul --seconds 45
python -I -u .\repro\cuda_probe.py cudnn_attention --seconds 45
```

이 파일은 실제 블랙스크린·GPU 이탈을 유발했던 부하다. 시험이 필요하다면 저장하지 않은 작업이 없는 별도 점검 환경에서 한 단계씩 판단해야 한다. 오류 또는 GPU 이탈 후 다음 부하를 연속 실행하면 안 된다. 자료를 검토하는 것만으로는 실행할 필요가 없다.

`--seconds`는 정상적으로 진행되는 반복문의 경과 시간 조건이다. CUDA 호출이 멈추면 해당 시간 내에 프로세스가 끝나리라는 보장이 없다. 원래 감독 코드에는 별도의 100초 프로세스 제한이 있었지만, 그것도 운영체제·GPU 복구를 보장하지 않는다. 강제 종료나 재부팅이 필요할 수 있다.

스크립트는 프로세스별 메모리 한도 35%, seed 20261110을 사용하며 전역 전력·클럭·TDR·드라이버·캐시 설정은 바꾸지 않는다. 하지만 GPU 메모리를 사용하고 연산을 실행하므로 상태 조회 전용 도구가 아니다. 스크립트의 `--help`도 모듈 import를 수행하므로 정적 검토에는 실행 대신 파일 읽기를 사용한다.
